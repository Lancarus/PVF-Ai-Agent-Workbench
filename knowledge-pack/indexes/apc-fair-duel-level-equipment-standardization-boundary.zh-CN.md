# 公平决斗 APC 等级与专属装备标准化边界

状态：需验证

## 当前可用结论

- APC 的装备配置可以是完整、稀疏或空列表；静态结构不存在必须照搬玩家整套装备的统一形态。
- 玩家与 APC 若需要长期独立调平，应使用不同 equipment ID 和不同 `.equ` 文件。
- 复制五件套时必须同步复制或改写 `[set item]` 成员关系。
- 无法通过 `equipment/equipment.lst` 解析的装备值不能按数字外形、槽位数量或相邻位置定性。
- 等级下降会改变职业成长得到的基础攻防与生命等数值，不能默认只靠 `[attack damage rate]` 补偿。
## 静态标准化没有证明

- 没有证明所有 APC 在目标等级都能学习或运行原技能。
- 没有证明高于 APC 等级的装备一定生效或一定失效。
- 没有证明所有武器、防具技能加成和触发效果都可以安全删除。
- 没有证明时装选择能力、称号、辅助装备、魔法石或 unresolved 值的统一槽位语义。
- 没有证明一个职业的结果可以直接外推到其他职业、其他 AI 或新副本整条路线。
- 没有给出等级成长、装备属性、AIC 倍率和最终伤害之间的精确公式。

## 风险分级

| 情况 | 默认处理 |
| --- | --- |
| 纯攻防、HP/MP和三速 | 可进入专属装备基线对照；仍需实机。 |
| 固定技能等级或技能数据 | 记录受影响技能；观察职业节奏是否退化。 |
| `[if]` / `[then]`、appendage、状态、召唤、霸体、复活 | 视为机制装备，不直接舍弃。 |
| 魔法石、时装、辅助装备或称号已解析 | 逐件审计，首轮可保留。 |
| 装备值无法解析 | 保留并标为 unresolved。 |
| 多 APC 共享同一装备文件 | 修改前列出全部影响对象，优先拆成 APC 专属文件。 |

## 扩展边界

- 后续为多张公平决斗副本制作大量 APC 时，可以复用“专属装备池＋单体代表验证”的流程。
- 装备池本身可以共享，但每个 APC 的职业机制审计和实机体验仍是独立验收层。
- 一轮只解决一个主要体验问题；等级与标准装备可以作为同一个基线实验包，AI 节奏、技能异常和特殊生存机制另分轮处理。
