# 技能树布局与多职业合并安全流程

状态：需验证

## 目标

审计 SP / TP 技能树节点、坐标和连线，并为多职业技能展示合并生成最小 preview。流程只处理显示布局；任何可学职业扩大必须另行授权和审阅。

## 阶段一：职业闭合

1. 从 `skill/skilllist.lst` 选择目标职业分支，再读取其技能 registry。
2. 分别读取对应 `*_sp.co`、`*_tp.co`；PVP 表和 `.chr` 默认技能作为独立入口。
3. `atfighter/atgunner/atmage` 等独立分支不与基础职业、觉醒、TP 或 Ex 合并。

## 阶段二：布局审计

1. 按原始 segment / `[character job]` 解析节点，记录 skill ID、路径、X / Y 和 `[next skill]`。
2. 报告 registry 未解析、重复技能、坐标冲突、重复格位、跨 segment 连线和异常环候选。
3. 对每个技能读取 `.skl` 的学习 / growtype 相关字段，但只作为并列审计，不用它重建布局全文。
4. 保留未知 segment、注释、顺序和格式。

## 阶段三：合并 preview

1. 用户明确选择源职业、目标 segment、主动 / 被动过滤和 SP / TP 范围。
2. 候选技能按“职业 registry + skill ID”去重，不能只按名称或裸 ID。
3. 新节点只加入目标指定 segment；不清空基础职业段，不覆盖其他段。
4. 坐标按用户规则分配，并报告冲突 / 溢出；不能因为画布能放下就认为可学。
5. `[next skill]` 只在两端节点和方向都闭合时进入计划。

## Learnability 隔离

- 合并节点不会自动修改 `.skl` growtype 适配。
- 不自动把新技能设为所有 growtype `0..4` 可学。
- 若用户另行要求扩大可学职业，作为第二个原子变更审阅 `.skl`、费用、前置、SP / TP、PVP、默认技能和服务端边界，并单独 dry-run。

## 写入交接

1. 从目标 CO 当前 raw no-simplified 文本建立节点级 change-set。
2. 每个被修改 segment 提供 before / after、冲突和未修改块摘要。
3. dry-run 未阻塞后才可生成新输出 PVF；不覆盖源文件，不写客户端资源。

## 实机批次

一个批次可以合并检查多个代表技能：树上可见、坐标 / 连线不重叠、SP / TP 分类正确、原技能未消失、未授权职业没有获得学习权限。运行技能效果仍按技能专项另验。

高风险优先口径：若静态 readback 已证明只增加显示节点且 `.skl` 未改，实机首先检查非适配 growtype 是否实际获得学习权限。节点被运行时过滤，或节点可见但不能学习，都可判为安全结果；实际能够学习才是 P1。不要把其他目标的结果继承到当前 PVF。

若 TP 不可学习是因为基础 SP 本身不可学习，只记录“非适配分支没有获得 TP 权限”；不得同时声称 TP 的基础技能等级前置、TP 扣费或最高等级已被独立验证。该高风险关闭后，不为普通 UI、换角或全技能普遍性单独追加批次。
