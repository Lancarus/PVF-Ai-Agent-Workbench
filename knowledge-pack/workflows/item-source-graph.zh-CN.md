# 物品来源图只读流程

状态：默认可用

## 目标

从目标 PVF 反向回答“这个物品从哪里来”，把任务、掉落、商店、礼包、摇号和配方的引用汇成只读来源图，而不默认重写 itemdictionary 大表。

## 输入

- 目标 PVF 与完整 SHA256。
- 一个 registry-aware selector：物品路径，或“registry + ID”。
- 可选来源类别和路径前缀。

## 阶段一：解析物品身份

1. 路径输入通过正确 registry 反查 ID；数字输入必须同时声明 registry。
2. 读取目标物品脚本，记录 equipment / stackable 等实体类型和名称候选。
3. 不把名称、图标或数字范围作为主键。

## 阶段二：扫描来源桶

按需读取而不是默认全包加载：

1. 任务固定 / 可选、邮件、接取、通关、怪物 / 敌人奖励。
2. 独立掉落与副本等级掉落。
3. NPC 商店、加百利、商城。
4. 礼盒、随机 / 自选礼包、魔盒。
5. 摇号与设计图。
6. 目标存在的 itemdictionary 路径族，作为现有索引对照。

每条来源边记录路径、父块、item ID 位置、数量 / 权重 / 条件候选、解析状态和是否动态脚本引用。

## 阶段三：对照与去重

- 同一路径同一父块的重复引用可以聚合计数，但保留原始位置。
- itemdictionary 中有记录而原引用未找到时标记 `dictionary-only`，不能直接当事实。
- 原引用存在而字典未列出时标记 `source-only`，不能据此自动改表。
- 动态 NUT/SQR、模板路径、读取失败和截断进入 unresolved。

## 输出

- 物品 registry 身份和目标 readback。
- 按来源类别分组的反向边。
- dictionary-only、source-only、unresolved、读取失败和截断。
- 若 0 条命中，明确写“本次静态范围未观察到”，不写“无法获得”。

## 写入边界

来源图默认只读。若用户明确要求修复 itemdictionary，先以目标最近邻行形和原始来源边建立独立 preview；不得直接用生成图覆盖整张字典。
