# 独立掉落规范化与英雄档候选补全流程

状态：需验证

## 目标

只读识别 `independent_drop.etc` 中可复用的内联掉落池，并对明确列形的 type 0 / 1 行生成英雄档补全 preview。默认不写 PVF。

## 阶段一：目标形状审计

1. 记录目标 PVF SHA，并读取 `etc/independent_drop.etc`、`etc/independentdrop.lst` 和少量已登记 sidecar。
2. 识别 `[independent drop]` 与 `[list]` 的真实块边界、结束标签、行首 type、列数、注释和空列。
3. 不用其他版本的列数覆盖目标；任何未知分支记为 `shape-unresolved`。

## 阶段二：内联列表规范化 preview

1. 只在已闭合的内联 `[list]` 中抽取规范化 token 序列。
2. 建立内容 fingerprint，找出重复列表。
3. 先读取所有已登记 sidecar；若存在相同内容，复用既有 ID。
4. 没有可复用项时，从目标 registry 选择无冲突 ID 和新相对路径。
5. 生成原子计划：新 sidecar、`independentdrop.lst` 登记、主体引用替换。
6. 保留读取失败、未解析 item ID、registry 冲突、只出现一次和格式多义项。

规范化目标是减少重复维护，不是改变掉落候选、权重、顺序或概率。

## 阶段三：英雄档 preview

1. 遍历 `[independent drop]` 主体，进入 `[list]` 后立即停止解释英雄列，直到该块闭合。
2. type `0` 只检查 0 起索引 `3..6 -> 7`；type `1` 只检查 `4..7 -> 8`。
3. 英雄位为 `0` 或 `-1`、前四档至少一个正值时，取最后一个正值。
4. 用户必须显式选择比例；`1.5` 只能显示为可修改起点。
5. 候选值为“最后一个正值 × 比例”四舍五入；输出旧值、新值、比例、行路径和原始 token。
6. 列数、type 或块上下文不符时不补值。

## 阶段四：写入交接

- 列表抽取与英雄档修改分成两个 change-set 类别，可组合 dry-run，但分别汇报。
- previousText / newText 从目标当前 raw no-simplified 文本建立。
- sidecar、registry 和主体引用任何一项失败时，规范化原子组整体阻断。
- 不把静态数值补齐写成实机掉率、英雄难度入口或奖励发放证明。

## 高收益实机批次

只有准备分发输出且仍有静态无法替代的高风险时才安排。优先把多个代表项合并到一个批次，不为每行、每个候选池或普遍性覆盖单独测试。

1. sidecar、registry 和主体引用已静态闭合时，选择一个稳定入口完成启动、目标怪物击杀、清图和清算；这只验证新路径没有造成读取异常。
2. 未实际掉出某个候选物不判失败，也不把短样本写成候选池、权重或概率证明。
3. type `0` / `1` 的英雄列必须分别保留静态 readback；只有客户端确实提供英雄难度入口时才测试运行行为。
4. 登陆器不支持英雄入口时记录 `BLOCKED_CLIENT_ENTRY`，不记 PVF `FAIL`，也不为同一阻断单独消耗重测预算。
5. 普通难度的 non-hero smoke 不证明英雄列，也不证明 type `1` APC 的生成与掉落行为。
