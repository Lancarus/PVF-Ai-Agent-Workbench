# 双 PVF 语义对比与结果集分析流程

状态：默认可用

## 目标

在不写 PVF 的前提下，对两个 SHA 锁定封包做路径集合与解析后语义对比，并用可重复的结果集运算收窄批量分析范围。

## 输入

- 右侧 / 对照 PVF 与完整 SHA256，并声明其角色。
- 路径前缀、扩展名、字符串、数字或 resolve 条件之一。
- 最大结果数和截断处理。

## 封包对比

1. 分别枚举并规范化路径，输出 `only-left / only-right / common`。
2. 共有路径先读取双方原始内容，再按声明的 StringTable / 文本解析方式比较语义。
3. 解析成功才进入 `common-equal` 或 `common-different`；任一侧失败进入 `unresolved`。
4. 不以文件大小、压缩大小、条目数量或名称相同代替内容比较。
5. 列表显示上限只是报告约束；例如结果超过 5,000 时显式写 `truncated=true` 并要求继续分桶。

若已有外部 `pvf-lineage` catalog，可以查询其 SHA 绑定差分；catalog 仍是索引，关键结论必须读回两侧目标文件。

## 工作集查询

1. 初始查询模式选择 path、string、number 或 resolve。
2. 每次查询明确采用覆盖、并集或交集。
3. 在当前工作集上可用 Match 保留、Remove 剔除二次命中项。
4. 每一步记录条件、输入计数、输出计数、去重规则和 unresolved。

数字搜索结果必须保留文件、父块和候选 registry，不能把文本中相同数字统一解析为一个 ID。

## ST / Section 频次

- 统计 StringTable 引用和 Section 内容前，记录解析成功数与失败数。
- 输出频次、代表路径和影响面，不只输出一个总数字。
- 高频适合发现公共依赖，低频适合发现异常候选；二者都不等于错误或可安全替换。

## 批改交接

1. 原始工具的结果集写回规模上限不作为 Workbench 的安全许可；Workbench 应把任何批量写回继续分桶。
2. 每一类替换、内容删除、块增加 / 删除或 label 写入都先输出逐文件 preview。
3. 最终 previousText / newText 必须来自目标 PVF 当前 raw no-simplified 文本。
4. 结果集、语义 diff 或频次表不能直接 apply；改动必须重建为 change-set 并通过受控生命周期。

## 验收

- 两侧 SHA、角色和规范化路径规则明确。
- 截断、解析失败、只在单侧和语义差异分层可见。
- 每次集合运算可复述、可重放。
- 没有把高命中、高频次或高相似度写成安全写入结论。
