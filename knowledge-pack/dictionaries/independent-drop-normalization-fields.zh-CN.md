# 独立掉落规范化与英雄档词典

状态：需验证

## 路径族

| 路径 | 作用 |
| --- | --- |
| `etc/independent_drop.etc` | 独立掉落主体；不同版本的行结构可能明显不同。 |
| `etc/independentdrop.lst` | 独立掉落 sidecar ID 到文件路径的 registry。 |
| `etc/independentdrop/*.etc` | 可复用的独立掉落列表文件。 |

## 内联列表规范化

规范化候选将主体中的重复内联 `[list]` 抽成独立 sidecar，并在 `independentdrop.lst` 登记，再把主体改为引用 ID。

匹配重复列表时必须使用结构化 token 序列，不能仅按显示文本或空白归一化全文。若已有同内容 sidecar，应优先复用既有 ID。读取失败、未解析 item ID、registry 冲突和格式差异必须保留。

当前受控样本已确认：新 sidecar 文件、`independentdrop.lst` 登记和主体引用三者原子闭合后，目标怪物击杀、清图与清算可以作为“新路径未造成读取异常”的高收益实机 smoke。一次流程中没有掉出某个候选物不是失败，也不能据此证明候选池概率；同样，该 smoke 不证明 type 1 APC 行为。

## 英雄档候选列位

只有完成目标文件形状审计后，才可把以下 0 起 token 位置作为候选：

| 行首 type | 前四档候选 | 英雄档候选 |
| --- | --- | --- |
| `0` | 索引 `3..6` | 索引 `7` |
| `1` | 索引 `4..7` | 索引 `8` |

规则：

1. 只处理 `[independent drop]` 主体，必须跳过 `[list]` 块内所有内容。
2. 英雄档当前值只有为 `0` 或 `-1` 时才可进入候选。
3. 前四档至少有一个正值。
4. 取前四档中最后一个正值，乘以用户明确选择的比例并四舍五入。
5. 比例没有跨版本默认事实；`1.5` 只能作为可见、可修改的起点，不能静默采用。

如果 type、列数、块边界或前四档含义与目标样本不闭合，整行标记 `shape-unresolved`，不补值。

已验证边界：当前受控样本的 type `0` 与 type `1` 代表行具有不同 token 数量，且按上表各自列位完成静态 readback。不得用“行长应该一致”替代目标真实列形。若客户端或登陆器不提供英雄难度入口，将运行项记为 `BLOCKED_CLIENT_ENTRY`，不是 PVF `FAIL`；静态英雄位写入与 readback 仍不能提升为英雄难度行为成立。
